## Story

**As a** colaborador do Sítio Labareda,
**I want** acessar uma página web simples pelo link recebido no WhatsApp e ver minhas tarefas pendentes, marcá-las como concluídas e adicionar observações ou fotos,
**so that** eu possa registrar meu trabalho sem precisar ligar para o Marcos ou instalar nenhum aplicativo.

## Contexto e Objetivo

O painel é o ponto de encontro entre o colaborador (campo) e o sistema. Ele recebe o link via WhatsApp com um token JWT único, carrega sua lista de itens pendentes, e permite marcar conclusão, adicionar texto de observação e enviar foto de comprovação. Cada ação dispara o workflow WF-04 no n8n, que atualiza o banco e notifica o Marcos quando a tarefa inteira for concluída.

## Notas Técnicas

**Decisão arquitetural: PWA via link (ADR-002):**
Escolhida sobre bot WhatsApp interativo e app nativo porque: zero instalação, suporta checklist visual com checkboxes, campo de texto e câmera, funciona offline. Colaboradores rurais não instalam apps.

**Autenticação por JWT no link (ARCH-001 §6.2, §6.5):**
- JWT assinado com `SUPABASE_JWT_SECRET`
- Payload: `{ "colaborador_id": "uuid", "tenant": "labareda", "exp": unix_24h }`
- Token no query parameter `?t={jwt}` — não há tela de login
- Expiração: 24h. Token renovado a cada novo disparo de tarefa.
- Rate limiting: max 100 requests/hora por token

**RLS do Supabase para o painel:**
O colaborador acessa via token JWT. As RLS policies das tabelas devem permitir ao colaborador ler/atualizar APENAS seus próprios `checklist_items`. Isso precisa ser configurado nas migrations (Story 1.1 pode não ter incluído RLS — verificar e adicionar se necessário).

**Stack do PWA (ARCH-001 §6.3):**
- HTML + CSS + JS vanilla (ou Preact para reatividade mínima)
- Sem framework pesado (deve carregar rápido em 4G rural)
- Service Worker: cache `checklist_items` do colaborador com Workbox ou manual
- Manifest.json para PWA installability

**Wireframe Tela 1 (ARCH-001 §6.4):**
```
Olá, {nome}!
{propriedade} — {data}

JARDINAGEM
[ ] Podar palmeiras da entrada
[ ] Regar horta orgânica
[x] Limpar canteiro central

LIMPEZA
[ ] Limpar piscina
```

**Wireframe Tela 2 (detalhe ao tocar no item):**
```
< Voltar
{descricao do item}
Setor: {setor}
Status: [ ] Concluído
Observação: [textarea]
Foto: [Tirar Foto] [Galeria]
[CONFIRMAR]
```

**Upload de foto:**
- Aceitar: JPEG, PNG, WEBP, máx 5MB
- Compressão no cliente antes do upload (Canvas API)
- Path no Storage: `labareda/fotos/{colaborador_id}/{item_id}-{timestamp}.jpg`
- Salvar URL pública em `checklist_items.foto_url`

**WF-04-LAB no n8n (Webhook conclusão):**
```
POST /webhook/checklist-complete
→ Validar JWT
→ Extrair colaborador_id, tenant
→ UPDATE checklist_items SET status='concluido', observacao, foto_url, concluido_at
→ O trigger do banco (trg_verificar_conclusao) atualiza a tarefa automaticamente
→ SELECT status FROM tarefas WHERE id = $tarefa_id
→ IF concluida: Telegram para Marcos "Tarefa concluída: '{cmd}' por {colaboradores}"
→ ELSE: Telegram opcional (configurável) "Item concluído: '{item}' por {nome}"
```

**Bucket para fotos:**
[AUTO-DECISION] Usar bucket separado `fotos-comprovacao` em vez de `relatorios` para fotos (reason: Separação lógica e políticas de acesso diferentes — fotos de colaboradores são acessadas pelo painel com JWT do colaborador, PDFs de relatórios são acessados pelo Marcos via Telegram. Manter separados facilita políticas RLS e limpeza periódica.)

## Testing

- Abrir URL com JWT válido em celular real → lista de itens aparece
- Abrir URL com JWT expirado → tela de erro amigável
- Marcar item como concluído → confirmar UPDATE no banco via Supabase Studio
- Adicionar observação → confirmar em `checklist_items.observacao`
- Upload de foto → confirmar URL em `checklist_items.foto_url` e arquivo no Storage
- Marcar todos os itens de uma tarefa → verificar notificação no Telegram do Marcos
- Desligar rede no celular → lista de itens ainda exibida (cache offline)
- Reconectar → ações pendentes sincronizadas
- Testar em Chrome Android e Safari iOS (mínimo)
