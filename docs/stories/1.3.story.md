## Story

**As a** Marcos (operador),
**I want** cadastrar, listar e remover colaboradores diretamente pelo Telegram,
**so that** eu possa gerenciar minha equipe sem precisar acessar nenhum sistema adicional.

## Contexto e Objetivo

Implementa o CRUD básico de colaboradores via chat Telegram. O Marcos poderá adicionar um colaborador (com nome, telefone e setor), listar os colaboradores ativos por setor, e desativar um colaborador. A operação é feita por comandos no chat do bot Labareda e processada pelo n8n.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1
**Prioridade:** Alta
**Estimativa:** M

## Critérios de Aceitação

- [ ] AC-1: Marcos pode adicionar colaborador enviando mensagem no formato reconhecível (ex: "Adicionar colaborador: Nome, +5573999999999, jardinagem") — o LLM interpreta a intenção de CRUD
- [ ] AC-2: Colaborador é inserido na tabela `labareda.colaboradores` com `nome`, `telefone` (formato E.164 `+5573999999999`), `setor_id` (lookup em `shared.setores`), `ativo = true`
- [ ] AC-3: Se o telefone não estiver no formato E.164 ou já estiver cadastrado, Marcos recebe mensagem de erro descritiva
- [ ] AC-4: Marcos pode listar colaboradores por setor enviando mensagem como "Listar colaboradores jardinagem" — recebe lista formatada no Telegram
- [ ] AC-5: Marcos pode desativar (soft delete) um colaborador por nome ou telefone — `ativo = false`, não exclui o registro
- [ ] AC-6: Colaboradores desativados não aparecem na listagem padrão e não recebem tarefas
- [ ] AC-7: Confirmação de cada operação enviada para o Marcos no Telegram (ex: "Colaborador João adicionado ao setor Jardinagem")
- [ ] AC-8: O campo `setor` aceita variações de linguagem natural (ex: "jardinagem", "jardim", "poda") — LLM mapeia para o setor correto de `shared.setores`

## Notas Técnicas

**Tabela `colaboradores` (schema labareda ou sao_miguel):**
```sql
id              UUID PK
nome            TEXT NOT NULL
telefone        TEXT NOT NULL UNIQUE  -- formato: +5573999999999
funcao          TEXT NOT NULL         -- texto livre (ex: 'jardineiro', 'camareira')
setor_id        UUID NOT NULL FK → shared.setores(id)
whatsapp_jid    TEXT                  -- preenchido pela Evolution API depois
ativo           BOOLEAN DEFAULT true
observacoes     TEXT
created_at, updated_at TIMESTAMPTZ
```

**Constraint de telefone:**
```sql
CONSTRAINT telefone_format CHECK (telefone ~ '^\+\d{10,15}$')
```
Formato obrigatório: `+5573999999999` (código país + DDD + número)

**Detecção de intenção via LLM:**
Ampliar o system prompt do WF-01-LAB para detectar intenção:
- `"intent": "criar_tarefa"` → fluxo principal (Story 1.4)
- `"intent": "adicionar_colaborador"` → CRUD
- `"intent": "listar_colaboradores"` → CRUD
- `"intent": "remover_colaborador"` → CRUD

Alternativa: comandos com prefixo fixo (ex: `/add`, `/list`) — mais simples e robusto.
[AUTO-DECISION] Usar prefixo de comando (`/add`, `/list`, `/remove`) para CRUD de colaboradores, LLM apenas para criar tarefas (reason: CRUD de colaboradores é operação administrativa menos frequente; prefixos fixos eliminam ambiguidade e risco de interpretação errada pelo LLM em operações sensíveis como remoção.)

**Comandos sugeridos:**
- `/add colaborador Nome, +5573999999999, jardinagem`
- `/list colaboradores [setor]`
- `/remove colaborador Nome ou +5573999999999`

**Lookup de setor:** `SELECT id FROM shared.setores WHERE nome ILIKE $setor_input LIMIT 1`

**Soft delete:** `UPDATE colaboradores SET ativo = false, updated_at = now() WHERE telefone = $tel`

**whatsapp_jid:** Campo preenchido quando a Evolution API confirma o JID do WhatsApp do colaborador (Story 1.4). Inicialmente NULL.

**Fonte:** ARCH-001 §3.3 (DDL completo de `colaboradores`), PRD-001 FR-1.1
