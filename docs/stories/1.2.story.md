## Story

**As a** Marcos (operador),
**I want** enviar comandos em linguagem natural pelo Telegram e receber confirmação de que o agente interpretou corretamente o setor e as tarefas,
**so that** eu possa comandar minha equipe sem precisar aprender sintaxe especial ou preencher formulários.

## Contexto e Objetivo

Implementa o núcleo do sistema: o workflow n8n que recebe mensagens do Telegram, aciona o LLM para interpretar o comando em linguagem natural, valida a resposta e confirma para o Marcos. Esta story cobre apenas a interpretação — a criação de tarefa e disparo WhatsApp é Story 1.4.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1 (parcialmente M6 — mesma lógica, webhook diferente)
**Prioridade:** Alta
**Estimativa:** M

## Critérios de Aceitação

- [ ] AC-1: Bot Telegram Labareda criado via BotFather e token configurado na tabela `configuracoes` do schema `labareda`
- [ ] AC-2: Webhook do bot configurado apontando para n8n (`POST https://n8n.labareda.com.br/webhook/telegram-labareda`)
- [ ] AC-3: Workflow n8n `WF-01-LAB` ativo, recebendo mensagens do Telegram
- [ ] AC-4: Mensagens de outros chat_ids (não o chat_id do Marcos) retornam "Acesso não autorizado" e não processam
- [ ] AC-5: LLM (gpt-4o-mini) interpreta o comando e retorna JSON válido com campos: `setor`, `items` (array), `prioridade`, `data_limite`
- [ ] AC-6: Se o setor retornado pelo LLM for inválido (não está em shared.setores), o bot responde pedindo reformulação
- [ ] AC-7: Se `items` vier vazio ou a resposta do LLM não for JSON válido, o bot responde com mensagem de erro amigável
- [ ] AC-8: Se o LLM retornar `{ "erro": "..." }`, o bot encaminha a mensagem de erro para o Marcos
- [ ] AC-9: Marcos recebe confirmação da interpretação antes do disparo: "Entendido! Setor: {setor}. Tarefas: {lista}. Confirmar? (Sim/Não)" — **ou** prossegue direto (configurável)
- [ ] AC-10: Temperatura do LLM fixada em 0.1 para respostas determinísticas
- [ ] AC-11: Variáveis de ambiente do workflow configuradas: `TENANT_SCHEMA`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `LLM_API_KEY`, `LLM_MODEL`

## Notas Técnicas

**System Prompt LLM (conforme ARCH-001 §5.3):**
```
Você é um assistente de gestão de equipes de uma pousada.
Seu trabalho é interpretar comandos em linguagem natural e extrair:

1. setor: um dos seguintes: jardinagem, limpeza, servico_quarto, manutencao, cozinha
2. items: lista de tarefas individuais (checklist)
3. prioridade: baixa, normal, alta ou urgente (default: normal)
4. data_limite: se mencionada (formato YYYY-MM-DD), senão null

Responda SOMENTE em JSON válido:
{
  "setor": "string",
  "items": ["string"],
  "prioridade": "string",
  "data_limite": "string|null"
}

Se o comando não for sobre tarefas de equipe, responda:
{ "erro": "Comando não reconhecido como tarefa de equipe" }
```

**Validação do setor:** Query em `shared.setores WHERE nome = $setor AND ativo = true`. Se não encontrar, resposta de erro.

**Segurança do webhook Telegram:**
- Filtrar por `chat_id` do Marcos (salvo em `configuracoes.telegram_chat_id_marcos`)
- Outros chat_ids: retornar "Acesso não autorizado" sem processar

**Variáveis de ambiente n8n:**
- `TENANT_SCHEMA`: `labareda`
- `SUPABASE_URL`: URL da instância Supabase
- `SUPABASE_SERVICE_KEY`: service_role key do Supabase
- `LLM_API_KEY`: chave da API OpenAI (ou outro provider)
- `LLM_MODEL`: `gpt-4o-mini` (padrão)

**Modelo LLM:** gpt-4o-mini — custo estimado < USD 1/mês com 5-20 chamadas/dia (ARCH-001 §5.3).

**URL do webhook n8n:** `https://n8n.labareda.com.br/webhook/telegram-labareda`

**Configurar webhook do Telegram:**
```
GET https://api.telegram.org/bot{TOKEN}/setWebhook?url=https://n8n.labareda.com.br/webhook/telegram-labareda
```

**Separação Labareda / São Miguel:** Esta story cria WF-01-LAB. A story 1.9 replica para São Miguel (WF-01-SM) com webhook diferente e tenant próprio.

**Fonte:** ARCH-001 §4.1, §5.1, §5.3

## Testing
