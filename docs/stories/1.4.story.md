## Story

**As a** Marcos (operador),
**I want** enviar um comando de tarefa pelo Telegram e que o sistema automaticamente crie o checklist e dispare as tarefas para os colaboradores do setor via WhatsApp,
**so that** minha equipe receba as instruções direto no celular sem eu precisar falar com cada um individualmente.

## Contexto e Objetivo

Este é o fluxo principal do sistema: Marcos envia um comando → LLM interpreta → tarefa criada no banco → checklist items criados e atribuídos → WhatsApp disparado para cada colaborador com link do painel → confirmação para Marcos no Telegram. É o coração operacional do Módulo 1.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1
**Prioridade:** Alta
**Estimativa:** G

## Critérios de Aceitação

- [ ] AC-1: Após interpretação LLM (Story 1.2), o workflow cria um registro em `tarefas` com: `comando_original`, `setor_interpretado`, `setor_id`, `prioridade`, `data_limite` (se houver), `telegram_message_id`, `telegram_chat_id`, `origem = 'comando'`
- [ ] AC-2: Para cada item retornado pelo LLM, um `checklist_item` é criado com: `tarefa_id`, `descricao`, `ordem`, `colaborador_id` (atribuição por round-robin entre colaboradores ativos do setor)
- [ ] AC-3: Se o setor não tiver colaboradores ativos, Marcos recebe mensagem de alerta: "Nenhum colaborador ativo no setor {setor}. Cadastre colaboradores antes de criar tarefas."
- [ ] AC-4: Para cada colaborador com itens atribuídos, a Evolution API dispara uma mensagem WhatsApp com: saudação, lista numerada de tarefas, link do painel com token JWT
- [ ] AC-5: Após o disparo, `checklist_items.whatsapp_enviado = true` e `whatsapp_enviado_at = now()` são atualizados
- [ ] AC-6: Marcos recebe confirmação no Telegram: "Tarefa criada! {n} itens enviados para {nomes_colaboradores} ({setor})."
- [ ] AC-7: Se a Evolution API falhar, o workflow registra o erro, marca `whatsapp_enviado = false` e notifica Marcos: "Tarefa criada mas WhatsApp falhou para {nome}. Tente reenviar."
- [ ] AC-8: Token JWT incluído no link do painel tem validade de 24h e contém: `colaborador_id`, `tenant` (labareda), `exp`
- [ ] AC-9: Toda a operação (interpretação → banco → WhatsApp → confirmação) é concluída em menos de 30 segundos (NFR-1 do PRD-001)

## Notas Técnicas

**Template de mensagem WhatsApp (ARCH-001 §5.2):**
```
Olá {nome}! 

Novas tarefas para você hoje ({setor}):

1. {item_1}
2. {item_2}
3. {item_3}

Marque como concluído no painel:
{painel_url}?t={jwt_token}
```

**Algoritmo de atribuição round-robin:**
Se há 3 itens e 2 colaboradores (A, B):
- item 1 → colaborador A
- item 2 → colaborador B
- item 3 → colaborador A
Cada colaborador recebe apenas SUA lista de itens no WhatsApp.

**Evolution API — endpoint de envio (ARCH-001 §5.2):**
```
POST {evolution_api_url}/message/sendText/{instance_name}
Headers: { "apikey": "{evolution_api_key}" }
Body: { "number": "+5573999999999", "text": "..." }
```
O `number` deve ser no formato E.164 (mesmo formato de `colaboradores.telefone`).

**Geração do JWT:**
- Secret: `SUPABASE_JWT_SECRET` (variável de ambiente n8n)
- Payload: `{ "colaborador_id": "uuid", "tenant": "labareda", "exp": unix_timestamp_24h }`
- URL do painel: `https://painel.labareda.com.br?t={jwt}`

**SLA:** Todo o fluxo deve concluir em < 30s (NFR-1). A chamada LLM é ~3-5s, Evolution API ~1-2s por mensagem, banco ~1s. Para 5 colaboradores, estimativa total < 20s.

**Tratamento de erro Evolution API:**
- Registrar erro no log do n8n
- Não bloquear o fluxo — notificar Marcos sobre o colaborador que falhou
- NÃO reverter a tarefa no banco (tarefa existe, WhatsApp falhou)

**Variáveis adicionais de ambiente:**
- `SUPABASE_JWT_SECRET`: segredo para assinar JWTs do painel
- `PAINEL_URL`: `https://painel.labareda.com.br` (ou URL de staging)
- `EVOLUTION_API_URL`: URL da instância Evolution
- `EVOLUTION_API_KEY`: API key da Evolution
- `EVOLUTION_INSTANCE_NAME`: nome da instância WhatsApp

**Fonte:** ARCH-001 §4.1 (fluxo completo WF-01), §5.2 (Evolution API), §6.2 (JWT do painel)
