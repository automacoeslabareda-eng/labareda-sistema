## Story

**As a** colaborador do Sítio Labareda,
**I want** receber automaticamente toda manhã uma mensagem WhatsApp com minha lista de tarefas pendentes,
**so that** eu não me esqueça de itens que ficaram em aberto e não precise acessar o painel sozinho para verificar.

## Contexto e Objetivo

Implementa o workflow WF-05-LAB: um cron diário às 08:00 que consulta todos os `checklist_items` com status `pendente` ou `em_andamento`, agrupa por colaborador e envia um lembrete via WhatsApp para cada um com seus itens em aberto. É uma automação de seguimento — não cria novas tarefas, apenas lembra dos pendentes.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1
**Prioridade:** Média
**Estimativa:** P

## Critérios de Aceitação

- [ ] AC-1: Workflow cron WF-05-LAB dispara diariamente às 08:00 (horário de Brasília, UTC-3)
- [ ] AC-2: O workflow consulta todos os `checklist_items` com `status IN ('pendente', 'em_andamento')` agrupados por `colaborador_id`
- [ ] AC-3: Para cada colaborador com itens pendentes, envia mensagem WhatsApp via Evolution API com: saudação com nome, contagem de pendentes, lista numerada dos itens, link do painel
- [ ] AC-4: Colaboradores sem itens pendentes não recebem mensagem (sem lembrete desnecessário)
- [ ] AC-5: O cron é silencioso para o Marcos (sem notificação no Telegram) — evita poluição do chat do operador
- [ ] AC-6: Se a Evolution API retornar erro para um colaborador específico, o erro é logado no n8n mas o cron continua processando os demais colaboradores

## Tarefas Técnicas

- [ ] Criar workflow n8n WF-05-LAB com Cron Trigger: `0 8 * * *` (08:00 todos os dias, UTC-3)
- [ ] Implementar nó "Buscar Pendências":
  ```sql
  SELECT c.nome, c.telefone, c.whatsapp_jid,
         ARRAY_AGG(ci.descricao) AS items_pendentes
  FROM checklist_items ci
  JOIN colaboradores c ON c.id = ci.colaborador_id
  WHERE ci.status IN ('pendente', 'em_andamento')
    AND c.ativo = true
  GROUP BY c.id, c.nome, c.telefone, c.whatsapp_jid
  ```
- [ ] Implementar IF: se `pendencias.length == 0` → STOP (sem ação)
- [ ] Implementar loop para cada colaborador com pendências
- [ ] Implementar nó "Disparar Lembrete WhatsApp" via Evolution API para cada colaborador
- [ ] Formatar mensagem de lembrete
- [ ] Implementar tratamento de erro por colaborador (não interrompe o loop)
- [ ] Testar com dados de colaboradores com pendências reais ou mock

## Notas Técnicas

**Cron n8n:** `0 8 * * *` — todos os dias às 08:00. Timezone: `America/Sao_Paulo` (UTC-3).

**Hora configurável:** A chave `lembrete_hora` em `configuracoes` (default: `08:00`) permite ajustar sem editar o workflow. Porém, o cron do n8n precisa refletir a hora configurada — alteração de horário requer edição do workflow. Para MVP, fixar em 08:00.

**Template da mensagem WhatsApp:**
```
Bom dia {nome}! 

Você tem {n} item(ns) pendente(s) hoje:

1. {item_1}
2. {item_2}
3. {item_n}

Acesse o painel para marcar como concluído:
{painel_url}?t={jwt_token}
```

**Observação sobre JWT no lembrete:**
Os lembretes precisam incluir um JWT válido no link do painel. Opções:
- (A) Gerar novo JWT a cada lembrete (24h de validade a partir do envio)
- (B) Consultar o JWT mais recente gerado para o colaborador
[AUTO-DECISION] Opção A: gerar novo JWT por lembrete (reason: Mais simples — não requer armazenar JWTs anteriores. O JWT tem validade de 24h, tempo suficiente para o colaborador usar o link. O custo de geração é mínimo, apenas assinatura HMAC.)

**Separação Labareda / São Miguel:**
Esta story cria WF-05-LAB. A story 1.9 cria WF-05-SM com a mesma lógica para o schema `sao_miguel`.

**Performance:** Para 15 colaboradores, são 15 chamadas à Evolution API. Com ~1s por chamada, total ~15s — bem dentro do SLA.

**Log n8n:** Registrar no log: `{data} — lembretes enviados: {n} colaboradores, {m} itens pendentes total`.
