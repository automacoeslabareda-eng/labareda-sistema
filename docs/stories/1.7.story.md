## Story

**As a** Marcos (operador),
**I want** receber automaticamente todo domingo um relatório semanal em PDF pelo Telegram com o resumo de todas as tarefas, percentual de conclusão por setor, observações dos colaboradores e pendências,
**so that** eu possa acompanhar o desempenho da equipe de forma consolidada sem precisar checar cada tarefa individualmente.

## Contexto e Objetivo

Implementa o workflow WF-03-LAB: cron semanal (domingo 20:00) que consolida os dados da semana, gera um PDF estruturado, salva no Supabase Storage e envia pelo Telegram. O relatório é o principal instrumento de acompanhamento gerencial do sistema.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1
**Prioridade:** Alta
**Estimativa:** G

## Critérios de Aceitação

- [ ] AC-1: Workflow cron WF-03-LAB dispara toda semana no domingo às 20:00 (horário de Brasília, UTC-3)
- [ ] AC-2: O workflow consulta todos os dados da semana corrente (segunda a domingo) usando a view `vw_dados_relatorio_semanal`

- [ ] AC-5: O PDF é salvo no Supabase Storage no bucket `relatorios`, path: `labareda/{ano}/{semana}/relatorio-semanal-{data}.pdf`

## Notas Técnicas

**Cron n8n:** `0 20 * * 0` — todo domingo às 20:00. Configurar timezone do n8n como `America/Sao_Paulo` (UTC-3).

**Período da semana:**
```sql
semana_inicio = date_trunc('week', CURRENT_DATE)::DATE  -- segunda-feira
semana_fim = CURRENT_DATE                                -- domingo (dia do cron)
```

**View `vw_dados_relatorio_semanal` (ARCH-001 §3.3):**
```sql
SELECT s.nome AS setor,
       COUNT(DISTINCT t.id) AS total_tarefas,
       COUNT(ci.id) AS total_items,
       COUNT(ci.id) FILTER (WHERE ci.status = 'concluido') AS items_concluidos,
       ...
       DATE_TRUNC('week', t.created_at)::DATE AS semana
FROM tarefas t
JOIN shared.setores s ON s.id = t.setor_id
LEFT JOIN checklist_items ci ON ci.tarefa_id = t.id
GROUP BY s.nome, DATE_TRUNC('week', t.created_at)::DATE
```
Filtrar por `semana = $semana_inicio` no workflow.

**Estrutura JSON consolidado (ARCH-001 §3.4):**
```json
{
  "propriedade": "Labareda",
  "semana": "2026-06-23 a 2026-06-29",
  "gerado_em": "2026-06-29T20:00:00-03:00",
  "resumo": { "total_tarefas": 12, "concluidas": 10, "pendentes": 2, "percentual": 83.33 },
  "por_setor": [...],
  "observacoes_destaque": [...],
  "pendencias": [...]
}
```

**Geração de PDF — Puppeteer via n8n Execute Command:**
```bash
# n8n Execute Command node
chromium-browser --headless --disable-gpu --print-to-pdf=/tmp/relatorio.pdf \
  --print-to-pdf-no-header file:///tmp/relatorio.html
```
Alternativa mais simples: usar `node-html-pdf` ou API externa se Puppeteer não estiver disponível na VPS.

**Template HTML do PDF:**
```html
<!DOCTYPE html>
<html>
<head>
  <style>
    body { font-family: Arial; font-size: 12px; margin: 20px; }
    .header { background: #2c5f2e; color: white; padding: 15px; }
    .setor { border: 1px solid #ccc; margin: 10px 0; padding: 10px; }
    .pendencia { background: #fff3cd; padding: 8px; margin: 5px 0; }
    .observacao { background: #e8f5e9; padding: 8px; margin: 5px 0; }
  </style>
</head>
<body>
  <div class="header">
    <h1>Relatório Semanal — Labareda</h1>
    <h2>{período}</h2>
  </div>
  <!-- resumo, por_setor, observacoes, pendencias -->
</body>
</html>
```

**Telegram sendDocument:**
```
POST https://api.telegram.org/bot{TOKEN}/sendDocument
Form: chat_id={chat_id}, document={pdf_binary}, caption="..."
```

**Upload Supabase Storage:**
Usar o endpoint REST do Supabase Storage com `service_role` key — permite bypass de RLS para upload server-side.
