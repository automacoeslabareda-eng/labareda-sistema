## Story

**As a** Marcos (operador),
**I want** ter o mesmo sistema de gestão de equipes funcionando de forma totalmente independente para o Sítio São Miguel, com seu próprio bot Telegram e sem nenhum cruzamento de dados com o Sítio Labareda,
**so that** eu possa gerenciar as duas propriedades separadamente pelo celular com total confiança de que os dados e equipes não se misturam.

## Contexto e Objetivo

Replica todos os 5 workflows n8n e o painel PWA para a propriedade São Miguel, operando sobre o schema `sao_miguel` do banco de dados (já criado na Story 1.1). O schema São Miguel tem estrutura idêntica ao `labareda`, mas dados completamente isolados. Esta story configura o segundo conjunto de bots, workflows e variáveis de ambiente.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M6
**Prioridade:** Alta
**Estimativa:** M

## Notas Técnicas

**Estrutura de pastas n8n (ARCH-001 §4.6):**
```
n8n
├── Folder: Labareda
│   ├── WF-01-LAB: Comando Telegram
│   ├── WF-02-LAB: Rotina Semanal
│   ├── WF-03-LAB: Relatório Semanal
│   ├── WF-04-LAB: Conclusão Item
│   └── WF-05-LAB: Lembretes Diários
│
└── Folder: São Miguel
    ├── WF-01-SM: Comando Telegram
    ├── WF-02-SM: Rotina Semanal
    ├── WF-03-SM: Relatório Semanal
    ├── WF-04-SM: Conclusão Item
    └── WF-05-SM: Lembretes Diários
```

**Variáveis de ambiente São Miguel (ARCH-001 §4.1):**
- `TENANT_SCHEMA`: `sao_miguel`
- `SUPABASE_URL`: mesma instância Supabase
- `SUPABASE_SERVICE_KEY`: mesma service_role key
- `LLM_API_KEY`: mesma API key
- `LLM_MODEL`: `gpt-4o-mini`
- `EVOLUTION_INSTANCE_NAME`: mesma instância Evolution (ADR-004) ou nome diferente se separada
- `PAINEL_URL`: `https://painel.saomiguel.com.br`

**PWA e tenant:**
O painel PWA é o mesmo código estático para ambas as propriedades. O tenant é inferido do JWT (`"tenant": "labareda"` ou `"tenant": "sao_miguel"`). A URL exibida no cabeçalho usa `configuracoes.nome_propriedade` carregada do schema correspondente.

**Isolamento verificável (ADR-001):**
```sql
-- No schema labareda: não deve ver dados do sao_miguel
SET search_path TO labareda;
SELECT COUNT(*) FROM colaboradores; -- apenas colaboradores Labareda

SET search_path TO sao_miguel;
SELECT COUNT(*) FROM colaboradores; -- apenas colaboradores São Miguel

-- Confirmar: nenhuma query faz JOIN entre schemas
```

**Chat_id Marcos — mesmo usuário, dois bots:**
Marcos pode usar o mesmo número de telefone para interagir com os dois bots. O `telegram_chat_id_marcos` será o mesmo valor numérico em ambos os schemas de configuracoes. Os bots são separados (tokens distintos), então não há conflito.

**Evolution API — instância compartilhada (ADR-004):**
Uma instância Evolution compartilhada entre Labareda e São Miguel. O isolamento é nos dados, não no canal de envio. A mensagem inclui o nome da propriedade para que o colaborador saiba de qual propriedade recebe a tarefa.

**Subdomínio `painel.saomiguel.com.br`:**
Requer: (a) registro do domínio saomiguel.com.br pelo cliente, OU (b) subdomínio de labareda.com.br como `sm.labareda.com.br`. [AUTO-DECISION] Usar `sm.labareda.com.br` como URL do painel São Miguel para MVP, até que o cliente forneça domínio separado (reason: Evita dependência de segundo domínio não confirmado no contrato. Pode ser migrado sem alteração de código — apenas atualização da configuracoes.url_painel.)
