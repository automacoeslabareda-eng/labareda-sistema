## Story

**As a** Marcos (operador),
**I want** configurar rotinas semanais recorrentes para cada setor e dia da semana, e que o sistema dispare automaticamente as tarefas para os colaboradores toda vez que o dia chegar,
**so that** eu não precise lembrar de criar tarefas repetitivas toda semana.

## Contexto e Objetivo

Implementa o sistema de rotinas recorrentes: Marcos cadastra templates de tarefas semanais via Telegram (ex: "Todo segunda-feira, jardinagem: regar horta, podar cerca-viva"), e o sistema dispara automaticamente às 07:00 do dia configurado, criando as tarefas e enviando WhatsApp para os colaboradores — exatamente como se Marcos tivesse enviado o comando manualmente.

**Épico:** Onda 1 — Gestão de Equipes (Módulos 1 + 6)
**Módulo:** M1
**Prioridade:** Alta
**Estimativa:** M

## Critérios de Aceitação

- [ ] AC-1: Marcos pode criar uma rotina semanal via Telegram especificando: nome da rotina, setor, dia da semana e hora de disparo
- [ ] AC-2: Marcos pode listar rotinas ativas por setor
- [ ] AC-3: Marcos pode desativar uma rotina sem excluí-la (`ativo = false`)
- [ ] AC-4: Cada rotina pode ter múltiplos `rotina_items` (tarefas template), com colaborador padrão opcional por item
- [ ] AC-5: Workflow cron WF-02-LAB executa diariamente às 06:00 e verifica se há rotinas configuradas para o dia da semana atual
- [ ] AC-6: Para cada rotina do dia, o workflow cria automaticamente uma `tarefa` com `origem = 'rotina'` e `rotina_id` preenchido
- [ ] AC-7: Os `rotina_items` da rotina são copiados como `checklist_items` da tarefa gerada (respeitando colaborador padrão se definido)
- [ ] AC-8: WhatsApp é disparado para os colaboradores exatamente como no fluxo manual (Story 1.4)
- [ ] AC-9: Marcos recebe notificação no Telegram quando as rotinas do dia foram disparadas: "Rotinas do dia disparadas: {n} tarefas, {m} colaboradores notificados."
- [ ] AC-10: Se não houver rotinas para o dia, o cron é silencioso (sem notificação para Marcos)

## Notas Técnicas

**Tabela `rotinas_semanais` (ARCH-001 §3.3):**
```sql
id              UUID PK
nome            TEXT NOT NULL
setor_id        UUID FK → shared.setores
dia_semana      INTEGER  -- 0=dom, 1=seg, 2=ter, 3=qua, 4=qui, 5=sex, 6=sab
hora_disparo    TIME DEFAULT '07:00'
ativo           BOOLEAN DEFAULT true
```

**Tabela `rotina_items`:**
```sql
id              UUID PK
rotina_id       UUID FK → rotinas_semanais (CASCADE DELETE)
descricao       TEXT NOT NULL
ordem           INTEGER DEFAULT 0
colaborador_id  UUID FK → colaboradores (opcional — colaborador padrão)
```

**Mapeamento dia da semana para PostgreSQL:**
- PostgreSQL `EXTRACT(DOW FROM CURRENT_DATE)`: 0=domingo, 1=segunda, ..., 6=sábado
- Mesma convenção usada em `rotinas_semanais.dia_semana`

**Cron n8n:** Schedule Expression `0 6 * * *` (06:00 todos os dias, UTC-3)
O n8n precisa estar configurado com timezone correto (America/Bahia ou America/Sao_Paulo UTC-3).

**Diferença entre tarefa manual e de rotina:**
- `tarefas.origem = 'comando'` → criada por Marcos manualmente (Story 1.4)
- `tarefas.origem = 'rotina'` → criada automaticamente pelo cron (esta story)
- `tarefas.rotina_id` preenchido apenas quando `origem = 'rotina'`

**Reutilização do disparo WhatsApp:**
A lógica de disparo da Story 1.4 (buscar colaboradores, gerar JWT, Evolution API, UPDATE whatsapp_enviado) deve ser extraída como sub-workflow n8n chamado tanto por WF-01 (manual) quanto por WF-02 (rotina). Isso evita duplicação.

**Atribuição de colaborador em rotina_items:**
Se `rotina_items.colaborador_id` está preenchido, o checklist_item herda esse colaborador padrão.
Se NULL, usa round-robin entre ativos do setor (mesma lógica do manual).
