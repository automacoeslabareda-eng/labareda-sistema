## Story

**As a** desenvolvedor da Onda 1,
**I want** o banco de dados Supabase configurado com todos os schemas, tabelas, índices, triggers, functions e seed data,
**so that** todos os workflows n8n e o painel PWA tenham uma camada de persistência correta e isolada por propriedade desde o primeiro dia.

## Contexto e Objetivo

Fundação de toda a Onda 1. Sem o banco configurado nada mais pode ser implementado ou testado. Cobre os schemas `labareda`, `sao_miguel` e `shared`, conforme ADR-001 (schemas separados, não tenant_id).

**Módulo:** M1 + M6 (infraestrutura compartilhada)
**Prioridade:** Alta

## Notas Técnicas

**Estratégia de schemas:**
Conforme ADR-001 (ARCH-001 §2.1), a decisão arquitetural é **schemas separados** (`labareda`, `sao_miguel`), NÃO tenant_id. Justificativa: requisito contratual de "isolamento TOTAL" e "banco próprio" (FR-6.1). Um bug no RLS nunca exporia dados cruzados com schemas separados.

**Estrutura de schemas:**
```
PostgreSQL (Supabase self-hosted)
├── schema: shared       → setores (lookup, somente leitura, sem RLS necessária)
├── schema: labareda     → 7 tabelas operacionais + views + functions
└── schema: sao_miguel   → estrutura idêntica ao labareda
```

**Tabelas do tenant schema (ordem de criação — respeitar FK):**
1. `colaboradores` — FK para `shared.setores`
2. `tarefas` — FK para `shared.setores`; FK opcional para `rotinas_semanais`
3. `checklist_items` — FK para `tarefas` (CASCADE DELETE) e `colaboradores`
4. `rotinas_semanais` — FK para `shared.setores`
5. `rotina_items` — FK para `rotinas_semanais` (CASCADE DELETE); FK opcional para `colaboradores`
6. `relatorios_semanais` — sem FKs externas
7. `configuracoes` — sem FKs

**Constraint importante em `colaboradores`:**
```sql
CONSTRAINT telefone_format CHECK (telefone ~ '^\+\d{10,15}$')
```
Telefone no formato E.164: `+5573999999999`

**Trigger de conclusão automática:**
O trigger `trg_verificar_conclusao` dispara `AFTER UPDATE OF status ON checklist_items` somente quando `NEW.status = 'concluido'`. Isso evita recursão e processamento desnecessário. A função verifica se TODOS os items da tarefa estão concluídos e atualiza `tarefas.status = 'concluida'` + `concluida_at = now()`.

**Configurações seed (9 chaves, ambos schemas):**
- `telegram_bot_token` (sensível)
- `telegram_chat_id_marcos`
- `evolution_api_url`
- `evolution_api_key` (sensível)
- `evolution_instance_name`
- `nome_propriedade`
- `relatorio_dia_semana` (default: `0` = domingo)
- `relatorio_hora` (default: `20:00`)
- `lembrete_hora` (default: `08:00`)

**Supabase Storage:**
Bucket `relatorios` para PDFs semanais. Path: `{tenant}/{ano}/{semana}/relatorio-semanal-{data}.pdf`

**Fonte:** ARCH-001 §3.2, §3.3, §3.4 — SQL completo disponível no documento de arquitetura.
